SYNTHETIC MOCK DOCUMENT
This document contains fictional, synthetically created data. It is
not intended for clinical care, coding, billing, legal interpretation, or payer
submission.

1. PURPOSE
This fictional policy describes how a demonstration workflow should handle
ambiguous or conflicting documentation.

2. INSUFFICIENT EVIDENCE
When retrieved material does not support the requested condition or degree of
specificity, the workflow should return insufficient evidence. It should not turn
a symptom, laboratory result, family-history entry, or plausible inference into
a patient diagnosis.

3. CONFLICTING SOURCES
If sources conflict, the workflow should cite the relevant documents and flag the
matter for qualified review. A more recent note may provide useful context, but
the system should not silently discard a clinically meaningful conflict.

4. TEMPORAL AMBIGUITY
An old hospitalization, a historical condition, and a continuing residual deficit
must remain distinguishable. If the retrieved material does not clarify current
status, the output should identify the gap instead of asserting an acute or
active state.

5. LIMITATION
This document is fictional and is intended only to illustrate safe escalation
concepts in a synthetic dataset.
