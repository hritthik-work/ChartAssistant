SYNTHETIC MOCK DOCUMENT
This document contains fictional, synthetically created data. It is
not intended for clinical care, coding, billing, legal interpretation, or payer
submission.

1. PURPOSE
This guide describes source-attribution expectations for a fictional retrieval
workflow. It does not establish legal, clinical, or payer documentation rules.

2. REQUIRED SOURCE ATTRIBUTES
Each ingested source should retain a stable document identifier, document type,
version, patient identifier when applicable, encounter date when applicable, and
section boundaries. A generated answer should cite the document and chunk or
section that supports each material claim.

3. PATIENT ASSOCIATION
Clinical facts must be associated with the patient identified in the document
metadata. A condition discussed in one patient's note cannot support an answer
about another patient. Documents without a patient identifier, including guides
and policies, are general references rather than patient-specific evidence.

4. MULTIPLE SOURCES
When a response synthesizes multiple documents, each claim should remain
traceable to the relevant source. The workflow should not cite an unrelated
document merely because it contains a similar diagnosis. If records conflict,
the conflict must be surfaced rather than hidden.

5. CITATION LIMITS
A citation proves only what its source states. A guide can explain an evidence
boundary, but it cannot prove that a patient has a condition. Conversely, a
clinical note can document a patient fact but cannot create a general payer rule.
